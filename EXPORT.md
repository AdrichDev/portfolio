# Manual Netlify export

The site remains a Next.js application for development. The export command uses Next's supported static output mode only for this build; it does not change the normal dev/start scripts or deploy anything.

## Build the upload

On Windows, with Node.js, pnpm and Windows PowerShell installed:

```powershell
pnpm install
pnpm export:netlify
```

Upload `exports/portfolio-netlify.zip` using Netlify Drop, or drag the complete `exports/portfolio-netlify` folder. The ZIP contains `index.html` at its root. Do not upload only the HTML: `_next`, the portrait and other generated files are required. The output is ignored by Git and regenerated by the command.

No Node server, API keys, account connection or external runtime assets are needed. Fonts and the portrait are bundled. Serve the folder over HTTP for local inspection; opening `index.html` through `file://` is not supported because asset URLs are root-relative.

## Optional final domain

The public domain is not known yet. Host-specific social URL/image metadata is intentionally omitted from the portable build instead of publishing localhost or an invented address. Once the real domain is known, set `NEXT_PUBLIC_SITE_URL` to that HTTPS origin before rebuilding to enable absolute social previews. The preview image itself is generated at build time.

## Check the artifact

With an existing Playwright installation available (see `tests/README.md`):

```powershell
node tests/static-export.mjs
```

This serves the actual export with a temporary, isolated static server and exercises it without Next.js. It checks all resources, runs the full responsive interaction journey and closes the test server. No deployment or sign-in is performed.
